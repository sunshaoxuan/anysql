# FIX-01 AnySQL 核心功能修复报告

**生效日期**: 2026-05-12  
**状态**: 已完成 (Verified)

## 1. 概述
本文档详细记录了 AnySQL 智能 SQL 分析平台在修复阶段识别的核心缺陷及其对应的解决方案。主要目标是恢复搜索功能的准确性、消除字符编码乱码、并确保护流水线（Pipeline）进度的可靠性。

## 2. 缺陷清单与根因分析 (Root Cause Analysis)

### 2.1 搜索结果字符集乱码
- **现象**: 搜索结果中的日文和中文字符显示为 `?` 或乱码。
- **根因**: 
    1. Python `json.dump` 默认使用 ASCII 编码（`ensure_ascii=True`）。
    2. 磁盘 I/O 未显式指定 `encoding="utf-8"`。
- **修复方案**: 
    - 强制所有 JSON 存取操作使用 `encoding="utf-8"`。
    - 在序列化时设置 `ensure_ascii=False`。

### 2.2 解析进度条停止与数据异常
- **现象**: 仪表板显示进度为 0% 或 `undefined`，且数字不会跳动。
- **根因**: 
    1. **内存隔离**: `AnalysisPipeline` 在 API 调用时被错误地重新初始化，导致前端拿到的不是后台任务操作的同一个对象。
    2. **异常阻塞**: 旧逻辑中的 `execute_with_healing` 机制因参数签名不匹配（TypeError）导致 AI 陷入无效的自愈循环，阻塞了任务推进。
- **修复方案**: 
    - 实现 `_progress_map` 单例管理，确保 API 和后台任务共享同一内存状态。
    - 简化解析逻辑，直接调用 Agent 核心引擎，绕过不稳定的中间件。

### 2.3 详情页 500 内部错误
- **现象**: 点击搜索结果的“详细”按钮时服务器崩溃。
- **根因**: 
    1. **模板拼写错误**: 代码中引用了 `detail.html`，但物理文件名是 `sql_detail.html`。
    2. **URL 解码失效**: 包含日文的 SQL ID 在 URL 中被编码，后端未执行 `unquote` 导致找不到磁盘文件。
- **修复方案**: 
    - 修正 `main.py` 中的模板名称引用。
    - 引入 `urllib.parse.unquote` 对路径参数进行强制解码。
